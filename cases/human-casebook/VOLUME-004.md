# Human Casebook — Volume 004

## Institutional Ecology / 机构生态：偏移与纠错如何跨机构传播

Ecology IDs: ECO-001 — ECO-006  
Status: active  
Created: 2026-09-11  
Author: Lu Cheng / 卢成 / Jack Lu

---

## 卷四目的

前三卷分别研究：

1. 单个系统如何偏移；
2. 单个系统如何纠错；
3. 相似系统为何走向相反结果。

卷四开始处理一个更接近现实的问题：

> **现实后果很少由一个机构单独制造。更多时候，偏移、信息、资金、责任、认证与纠错沿着多个机构之间的关系链传播。**

因此，机构不再只被看作孤立节点，而被看作关系网络中的节点。

本卷不引入新的宏大理论，只为既有 Human 框架增加一个关系层：

`节点状态 + 节点间关系 + 传播方向 + 延迟 + 反馈 → 系统级结果`

结合脏现实结构场论，可写成：

`关系 → 结构 → 场 → 可行路径集合 → 选择/反馈 → 结果`

这里的重点从“一个机构内部发生什么”转向：

- 谁给谁钱；
- 谁给谁权限；
- 谁向谁报告；
- 谁认证谁；
- 谁监督谁；
- 谁能否决谁；
- 谁依赖谁的基础设施；
- 谁承担最终后果；
- 一个节点的错误如何被下一节点放大、过滤、纠正或锁定。

---

## 通用边类型

Volume 004 统一使用以下关系边：

- `funds`：资金、支付、补贴、融资；
- `authority`：法律、行政、组织权限；
- `information`：报告、证据、数据、风险信号；
- `certification`：许可、资格、评级、同行评议；
- `enforcement`：执法、处罚、强制；
- `dependency`：技术、能源、供应、基础设施依赖；
- `oversight`：审计、监管、复核；
- `appeal`：申诉、上诉、再审、纠偏；
- `reputation`：声誉、排名、公众预期；
- `feedback`：结果回流、质量指标、事故调查、投诉。

任何一条边都可能既是稳定器，也可能成为偏移传播通道。

# ECO-001 — 医疗生态：患者 → 医院 → 支付方 → 药械 → 监管

## surface_chain

`患者 ↔ 医院/医生 ↔ 医保/保险支付方 ↔ 药企/器械企业 ↔ 监管机构 ↔ 专业协会/指南机构`

## verified_structure

以美国 Medicare 为例，CMS 明确将部分医院支付与质量和成本指标挂钩。Hospital Value-Based Purchasing Program 会依据死亡与并发症、医院感染、患者安全、患者体验、效率和成本等指标调整部分支付。也就是说，支付方并不是医疗链之外的被动付款者，而会通过支付规则影响医院行为。

## edge_map

- 患者 → 医院：症状、需求、知情同意、投诉、支付；
- 医院 → 患者：诊疗、风险解释、资源配置、出院决策；
- 支付方 → 医院：支付规则、报销目录、质量指标、审核；
- 医院 → 支付方：编码、病例、质量数据、费用申请；
- 药械企业 → 医院：药品、设备、临床资料、教育与商业信息；
- 监管 → 医院/药械：许可、合规、检查、处罚、上市后监管；
- 专业共同体 → 医院：指南、标准、认证、声誉。

## drift_propagation

一个支付或质量指标如果与真实健康结果距离过远，可能出现：

`支付规则 → 医院管理目标 → 科室指标 → 一线时间分配 → 患者体验/诊疗路径`

偏移不需要任何单一参与者“变坏”。每个节点都可能在局部理性下响应自己的约束。

例如：

- 支付方希望降低浪费；
- 医院希望保持财务可持续；
- 科室希望达标；
- 医生希望在有限时间内完成更多病例；
- 患者希望获得个体化注意。

这些局部目标并不天然一致。

## correction_propagation

同一条链也可以产生纠错：

`患者安全事件 → 数据上报 → 医院质量改进 → 支付/监管反馈 → 标准调整 → 一线流程改变`

因此“指标”本身不是敌人。关键是：

- 指标与真实使命的距离；
- 数据是否容易操纵；
- 是否存在多指标互校；
- 是否允许一线解释异常；
- 是否有患者结果回流。

## Human calibration

不能把医疗系统简化为“医院追求利润所以不负责”。更完整的结构是：

`临床使命 + 患者需求 + 支付规则 + 专业规范 + 资源稀缺 + 法律风险 + 商业供给 + 监管 + 质量反馈 → 实际医疗路径`

## evidence_anchor

- CMS Hospital Value-Based Purchasing Program.
- CMS Value-Based Programs.

# ECO-002 — 司法生态：执法 → 检察 → 辩护 → 法院 → 矫正 → 上诉/复核

## surface_chain

`案件/举报 → 警察/调查机构 → 检察机关 → 辩护方 → 法院 → 量刑/矫正 → 上诉/再审/监督`

## verified_structure

美国 Bureau of Justice Statistics 对刑事司法系统的官方流程说明，将常见流程分为进入系统、检察与审前、裁判、量刑与制裁、矫正等阶段，并明确指出裁量贯穿整个刑事司法系统：警察决定是否执法/调查/逮捕，检察官决定是否起诉、降格或撤诉，法官决定保释、接受认罪、定罪和量刑，矫正与假释机构也拥有后续裁量。

## edge_map

- 警察 → 检察：证据、调查叙事、嫌疑人、案件分类；
- 检察 → 法院：指控、证据、认罪协商、量刑建议；
- 辩护 → 法院：反证、程序异议、替代解释、权利主张；
- 法院 → 矫正：裁判、刑期、监督条件；
- 上诉/再审 → 下级系统：撤销、发回、纠错标准；
- 取证/鉴定机构 → 警检法：专业证据与不确定性表达。

## drift_propagation

前端错误可能被后续节点继承：

`初始怀疑 → 调查选择 → 证据集合 → 起诉叙事 → 庭审信息集 → 判决`

如果每一环只看到上一环筛选后的信息，而不重新检查原始不确定性，就可能出现“路径锁定”。

但这并不意味着后续机构只是橡皮图章。辩护、独立鉴定、证据规则、公开审理、上诉、再审等机制本来就是用来打断这种路径依赖的。

## correction_propagation

`独立辩护/鉴定 → 暴露矛盾 → 法院排除/纠正 → 上诉先例 → 改变未来调查与起诉规则`

纠错能否发生，取决于：

- 后续节点是否真正独立；
- 是否能接触原始材料；
- 是否有时间与资源重新验证；
- 错误承认是否成本过高；
- 上诉/复核是否可达。

## Human calibration

司法链的风险不应写成“警察抓错人，法院就一定跟着错”。更准确的是：

`前端路径依赖` 与 `后端独立纠错能力` 同时存在。

系统质量取决于两股力量的相对强弱。

## evidence_anchor

- Bureau of Justice Statistics, The Justice System.

# ECO-003 — 金融生态：央行/监管 → 银行 → 企业/家庭 → 市场 → 公众预期

## surface_chain

`央行/监管 ↔ 银行 ↔ 企业/家庭 ↔ 支付/资本市场 ↔ 存款人与投资者 ↔ 信息与评级机构`

## verified_structure

Federal Reserve 对银行监督的公开说明显示，监管不仅制定规则，也持续收集和分析银行数据、监督金融机构活动，并要求及时处理可能威胁安全稳健性的重大金融风险。

因此金融系统天然存在多层反馈：

`机构资产负债状态 → 监管数据 → 监督行动 → 银行资产/融资行为 → 市场与存款人预期 → 资金流 → 再改变机构状态`

## edge_map

- 央行/监管 → 银行：规则、资本/流动性要求、检查、指导；
- 银行 → 企业/家庭：贷款、支付、存款、信用创造；
- 企业/家庭 → 银行：存款、还款、违约、资金需求；
- 市场 → 银行：融资价格、资产价格、流动性；
- 公众预期 → 银行：存款稳定性或挤兑压力；
- 银行 → 监管：风险数据、资本状态、合规报告；
- 评级/媒体/社交网络 → 市场参与者：风险叙事与信号。

## drift_propagation

金融生态的特殊性在于：

> **关于系统状态的预期，本身能够改变系统状态。**

所以信息并不只是描述现实，还可能成为现实的一部分。

例如风险信号沿网络传播后，存款或融资行为会改变银行流动性，再反向验证或放大最初担忧。

## correction_propagation

相反，可信的透明度、资本缓冲、流动性安排、监督行动和明确的处置机制，也可以降低不确定性和恐慌传播。

关键变量包括：

- 风险数据是否及时；
- 监管是否能在风险变成危机前行动；
- 市场参与者是否理解真实损失与流动性问题的差别；
- 应急支持是否同时避免长期道德风险。

## Human calibration

金融中的“信任”不是纯心理学变量，而是嵌入制度、资产、流动性、法律承诺和信息结构中的协调变量。

## evidence_anchor

- Federal Reserve Board, Supervision & Regulation.
- HUMAN Casebook CASE-004 Silicon Valley Bank.

# ECO-004 — 科研生态：资助 → 大学/实验室 → 同行评议 → 期刊/数据 → 社会应用

## surface_chain

`资助机构 → 大学/研究所 → 研究团队 → 同行评议 → 期刊/数据库 → 其他研究者 → 医疗/产业/政策`

## verified_structure

NIH 当前采用两级评审：第一层由主要由外部科学专家组成的 Scientific Review Group 评估科学与技术价值；第二层由 Advisory Council/Board 进行进一步审议，最终由具体 Institute/Center 做资助决策。NIH 同时提供申诉渠道，在存在偏见、利益冲突、专业不足或重大事实错误时可请求重新考虑评审过程。

Human Genome Project 则提供另一个重要结构样本：Bermuda Principles 要求大型测序中心快速公开序列数据，把开放共享从个人美德转化为项目层规则。

## edge_map

- 资助机构 → 研究组织：资金、研究方向、评审标准；
- 研究者 → 资助机构：提案、结果、绩效、声誉；
- 同行评议 → 研究者：准入、评分、修改建议；
- 研究者 → 期刊/数据库：论文、数据、方法；
- 期刊/数据库 → 社群：可见性、引用、声誉；
- 社群 → 后续研究：复制、批评、扩展；
- 社会/产业 → 科研：需求、资金、应用压力。

## drift_propagation

如果资助、职位和声誉过度绑定单一代理指标，偏移可沿链条放大：

`资助偏好 → 研究选题 → 数据分析选择 → 发表选择 → 引用与晋升 → 下一轮资助`

这可能形成自我强化。

## correction_propagation

科研系统也拥有独特纠错边：

- 外部同行评议；
- 数据公开；
- 方法公开；
- 重复研究；
- 撤稿和更正；
- 多级评审；
- 申诉；
- 不同资助机构之间的竞争。

Bermuda Principles 说明，制度可以主动缩短“私有数据 → 公共知识”的延迟。

## Human calibration

科学不是“客观真理机器”，也不是“利益集团骗局”。它是一套带激励、声誉、资源和纠错机制的制度生态。它的可信度来自持续可纠错，而不是个体科学家天然无偏。

## evidence_anchor

- NIH Grants & Funding, peer review process.
- NHGRI Human Genome Project Fact Sheet.

# ECO-005 — 基础设施生态：能源 → 电力 → 通信/水/交通 → 公共服务

## surface_chain

`燃料/天然气 ↔ 发电 → 电网 → 通信/水务/交通/医院/支付 → 居民与企业`

## verified_structure

FERC/NERC 对 2021 年冬季风暴的最终报告表明，发电故障既来自设备冻结，也来自燃料供应问题；天然气生产下降的一部分又与供电中断有关。这意味着天然气与电力之间存在双向依赖，而不是简单的单向供应链。

## edge_map

- 燃料系统 → 发电：天然气、煤、核燃料等能源输入；
- 发电 → 燃料系统：天然气生产、加工、压缩等设施所需电力；
- 电网 → 通信：基站、数据中心、网络设备供能；
- 电网 → 水务：取水、处理、泵站、污水处理；
- 电网 → 医疗：设备、冷链、照明、信息系统；
- 通信 → 电网/政府：调度、监测、应急协调；
- 交通/物流 → 修复系统：人员、零件、燃料运输。

## drift_propagation

关键风险不是某个节点坏掉，而是：

`A 依赖 B，B 又依赖 A`

于是局部故障可变成反馈环。

当组织分别管理燃气、电力、通信、水和交通时，每个部门的本地图可能都是正确的，但系统级依赖图仍可能缺失。

## correction_propagation

纠错重点因此不只是“多备一台机器”，而是：

- 识别跨系统依赖；
- 保护关键上游节点；
- 建立跨机构联合演练；
- 共享极端情景；
- 明确恢复优先级；
- 避免一个系统的应急措施切断另一个系统的恢复能力。

## Human calibration

文明韧性不是“每个机构都很强”的总和，而更接近：

> **关键节点强度 × 跨节点关系质量 × 故障隔离能力 × 恢复协调能力。**

这仍是作者结构化表达，不是标准工程公式。

## evidence_anchor

- FERC/NERC, February 2021 Cold Weather Outages Final Report.
- HUMAN Casebook CASE-009.

# ECO-006 — 信息平台生态：创作者 → 平台算法 → 广告/商业 → 用户 → 监管/研究者

## surface_chain

`创作者/商家 → 平台 → 推荐系统 → 用户注意力 → 广告/交易 → 平台收益 ↔ 监管/研究者/公众监督`

## verified_structure

欧盟 Digital Services Act 已把推荐系统透明度、风险评估、研究者数据访问、广告库和内容审核理由等纳入治理结构。2026 年欧盟统一了透明度报告的机器可读格式；对超大型平台和搜索引擎，也要求提供非基于 profiling 的推荐选项等控制。

这说明平台生态中的“算法”不是孤立代码，而处于商业目标、用户行为、创作者策略、广告市场和监管要求的共同作用下。

## edge_map

- 创作者 → 平台：内容、元数据、行为信号；
- 平台 → 创作者：分发、流量、规则、收益；
- 用户 → 平台：点击、观看、购买、举报、离开；
- 平台 → 用户：排序、推荐、广告、审核；
- 广告主 → 平台：资金、转化目标；
- 平台 → 广告主：用户触达、归因、数据；
- 监管 → 平台：透明度、风险评估、申诉与审计要求；
- 研究者/公众 → 监管与平台：独立分析、外部问题定义。

## drift_propagation

当平台主要优化某个参与度指标时：

`用户反应 → 推荐系统学习 → 内容供给适配 → 更强用户反应 → 创作者继续适配`

于是平台不是单方面“操纵”用户，创作者、用户和算法可能共同形成反馈循环。

## correction_propagation

监管和平台治理可以插入新的边：

- 推荐系统透明度；
- 非个性化选择；
- 用户申诉；
- 研究者数据访问；
- 风险评估；
- 独立审计；
- 内容审核理由数据库。

这些机制不保证平台没有偏移，但会增加外部可见性与纠错入口。

## Human calibration

平台问题不应简化成“算法邪恶”。更准确的是：

`商业目标 + 排序目标 + 用户反馈 + 创作者适配 + 广告需求 + 治理边界 → 信息生态`

## evidence_anchor

- European Commission, Digital Services Act transparency and recommender-system materials.
- HUMAN Casebook CASE-011.

# 跨生态结论：错误不是只在节点里，也会存在于边上

Volume 004 得出的最重要修正是：

> **Institutional failure is often relational failure.**

一个机构内部没有明显错误，并不意味着系统整体没有问题。

典型结构包括：

### 1. handoff_loss

A 做完自己的工作，但关键信息没有完整传到 B。

### 2. responsibility_gap

A 以为 B 负责，B 以为 C 负责，最终没有节点拥有完整后果。

### 3. incentive_misalignment

A 的最优行为把成本转嫁给 B。

### 4. feedback_delay

真实结果很久之后才返回决策节点，导致错误长期存在。

### 5. boundary_blindness

每个机构都知道自己的内部结构，却没人维护跨机构依赖图。

### 6. correction_blocking

某节点已经发现问题，但缺少权限、接口或激励改变上游/下游行为。

### 7. correction_amplification

一个节点建立好的纠错机制，可以通过标准、支付、监管、公开数据或先例传到整个生态。

---

# 新的分析单位：path，而不仅是 node

过去的问题常写成：

> 医院有什么问题？

Volume 004 要求 Agent 改问：

> **这个具体结果沿着哪条路径生成？**

例如：

`支付规则 → 医院指标 → 科室排班 → 医生时间 → 患者体验`

或者：

`警察证据 → 检察选择 → 法院可见证据集 → 判决 → 上诉纠错`

或者：

`燃气冻结 → 发电不足 → 轮流停电 → 燃气设施失电 → 更多燃气下降 → 更多发电不足`

路径分析的优势是避免把复杂结果人格化成“某个机构想这么做”。

# Agent 使用协议

当问题涉及两个以上机构时，优先执行：

`IDENTIFY_NODES → IDENTIFY_EDGES → MAP_DIRECTION → MAP_RESOURCE_FLOW → MAP_INFORMATION_FLOW → MAP_AUTHORITY → MAP_DEPENDENCY → MAP_DELAY → MAP_FEEDBACK → MAP_DRIFT_PROPAGATION → MAP_CORRECTION_PROPAGATION → IDENTIFY_UNOWNED_GAPS`

必须区分：

- 节点内部失败；
- 节点间交接失败；
- 合法职责分工；
- 必要冗余；
- 无效重复；
- 真正的监管/责任空白。

不得因为存在多机构参与，就自动称为“官僚低效”。GAO 也明确指出，fragmentation / overlap / duplication 有时会造成低效，但某些重复或分散也可能是必要的，必须评估权衡。
