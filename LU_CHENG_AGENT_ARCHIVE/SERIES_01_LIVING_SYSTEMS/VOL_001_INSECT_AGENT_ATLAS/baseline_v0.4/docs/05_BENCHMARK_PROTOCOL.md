# BENCH-04-PILOT 预注册协议

研究问题保持不变：读取 Atlas 是否改变模型生成架构的机制分布？本轮检验“这份编译包作为上下文干预的效果”；不声称改变权重、不声称模型原本不知道事实，也不把模型能力提升当成已证实前提。

设计：3 个实际模型槽位 × 2 个冻结任务 × 3 次独立重复 × 3 个条件 = 54 次生成；每次两种架构，共 108 种。首轮可先执行 FIRST_THREE_CALLS.md 的三个调用排查流程，其结果仍要保留，不能择优替换。模型槽位未填具体名称，因为包内没有可验证版本，也没有本轮模型端点。

| 条件 | 输入差异 | 所回答的问题 |
|---|---|---|
| A | 无补充阅读 | 默认生成分布 |
| B | 十个压缩原语，含定义/条件/失效 | 当前 Atlas 编译干预后的分布 |
| C | 同词数、同编号格式的弱结构目录描述 | 泛阅读、长度与材料呈现的部分对照 |

B/C 均 365 个空白分隔单词；这不是任何特定模型的 Token 等长证明。C 使用假设性目录描述，不编造错误生物机制。B 已经以去领域名称的结构原语呈现，比 C 更有任务相关结构是设计的一部分；本试验无法单独归因于约束密度、结构语言或跨域组合。后续 D 组可用同格式、同结构密度的常规工程原语包，区分异质先验选择与一般结构化提示的作用；本轮不扩组。若另测生物名称效应，须新加同机制带/不带来源标签的成对条件。

生成约束：各组相同任务、输出 Schema、两种架构、固定工具/成本上限；不要求新颖，不禁止层级结构。每一次用新上下文，关闭记忆、项目附件、历史回复和联网。生成模型只见一个匿名 prompt 文件；不能给整个交接包。设置能控制则固定；不能控制记录 null 和同一路由，不伪造 temperature/seed。模型名与版本取自界面或 API 元信息，不问模型“你是什么版本”。

顺序在 model × task × replicate 区块内随机化，种子及提示哈希冻结。首轮后不得为获得更好答案重试。本地解析可以剥除一层 JSON 代码围栏，原始字节仍保留；拒答、结构错误或不完整输出保留为 invalid_output，主指标按该调用 0 分处理并单列无效比例。上下文污染则排除并报告缺失区块，不能当成 0 分掩盖污染。

评分分两阶段：

1. 两名独立评审分别评架构的距离、交互、涌现、证伪、可实现性及任务有效性；去掉名称、作者和 prior_trace。拓扑、记忆、适应位置、生命周期、资源策略由固定枚举编码。评审填写组别猜测，估计盲法泄漏。
2. 主评分锁定后，单独审查 prior_trace 是否指向实际材料以及是否只是标签。作者自称“Atlas 贡献 3 分”不进入主结论。三分贡献与独立新颖性需要额外机制消融/对照支持。

主指标：每个架构 distance × task_valid；同一调用的两个架构取均值，然后做同模型/任务/重复的 B−A 与 B−C。先报告每个模型，再给等权模型均值。两种架构不是两个独立样本。分布指标：在 model × task 内，对两名评审一致且任务有效的五维机制签名统计分布及 JSD（0–1）。报告分类分歧、无效率、组别猜测准确率；不要把小样本正 JSD 当显著证据。

该 pilot 只做描述性判断，不输出 p 值、确定成功结论或“强模型收益更高”。没有预先外部能力排序与足够样本，就不能做能力梯度推论。未来只有质量不下降、B 同时超过 A/C、机制确有改变且跨任务复现时，才值得投入更大验证。若 B≈C、只改名称或设计无效，冻结扩库并修材料。

运行代码：`tools/benchmark.py`；冻结配置：`benchmark/config.json`；评分锚点：`benchmark/RUBRIC.md`。实际调用记录为零时，输出 null 与 NO_REAL_RESULTS，不生成示意成绩。
